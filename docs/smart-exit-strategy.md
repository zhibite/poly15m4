## 二、信号入场逻辑（完整版）

### 2.1 入场前提条件（必须全部满足）

| 条件 | 阈值 | 依据 |
|---|---|---|
| **Core 6 共识数** | ≥ 3 / 6 | 共识越多 → 胜率越高 |
| **Advanced 过滤** | 非 CVD 反向 | CVD 反向为最强单信号，必须跳过 |
| **价格区间** | 0.20 ≤ UP/DOWN 价格 ≤ 0.60 | 极端价格不参与 |
| **窗口时间** | 窗口开启后 ≤ 6 分钟 | 超过截止时间本窗口不开单 |
| **无持仓** | 当前无仓 | 单单持仓，强制一单一仓 |

### 2.2 Core 6 指标详解

| 指标 | 同向条件（agree = True） | 不计入共识 |
|---|---|---|
| **RSI** | RSI 从 70+ 回落跌破 70 → 做 DOWN；RSI 从 30- 反弹突破 30 → 做 UP；**含背离检测** | RSI 在 45~55 中性区；RSI 偏多/偏空但无反转确认 |
| **MACD** | MACD 柱状图绿色放大 → 做 UP；红色放大 → 做 DOWN；**横盘时忽略** | ATR < $30（BTC）时 MACD 不可靠 |
| **VWAP** | 价格 > VWAP + RSI > 50 + MACD UP → 做 UP；反之做 DOWN | 单指标无确认不给方向 |
| **EMA 9/21** | EMA 金叉 → 做 UP；死叉 → 做 DOWN | 无交叉时给方向但**不计入共识** |
| **Bollinger Bands** | 价格触及/突破布林上轨 → 做 UP；触及/跌破下轨 → 做 DOWN | 价格在带内震荡 |
| **Pivot** | 价格突破 HL10 高点 → 做 UP；跌破 → 做 DOWN | 价格在中间区 |

### 2.3 Advanced 5 过滤规则

| 过滤指标 | 信号方向与 Core 同向 | 信号反向 Core | 说明 |
|---|---|---|---|
| **CVD** | CONFIRM（吸筹/派发确认） | **SKIP（必须跳过）** | Z > 1σ 才视为有效信号 |
| **Funding** | 可作参考 | ≥ +0.08% → REDUCE（建议减仓） | 极端反向Funding覆盖确认信号 |
| **OBI** | 参考 | OBI 反向 → REDUCE（建议减仓） | 订单簿深度失衡 |
| **OI** | 价格上涨+OI上涨 → UP；价格下跌+OI下跌 → DOWN | 无明确反向逻辑 | 新多/新空入场确认 |
| **Liquidation** | UP: 空头清算密集区在上方；DOWN: 多头清算密集区在下方 | 无明确反向逻辑 | 清算墙作为价格磁铁 |

### 2.4 仓位确定规则

基础仓位为 **4U**，按 Core 6 共识数量确定实际买入金额：

| Core 共识数 | 信号强度 | 买入金额 | 说明 |
|---|---|---|---|
| 6 / 6 | 完美信号 | 8U（2× 基准） | 极强信号，全力做 |
| 5 / 6 | 极强信号 | 6U（1.5× 基准） | 强信号，重仓 |
| 4 / 6 | 标准信号 | 4U（1× 基准） | 标准信号，正常做 |
| 3 / 6 | 试探信号 | 2U（0.5× 基准） | 信号不足，半仓试探 |
| < 3 / 6 | 信号不足 | **禁止入场** | 共识不够，必须跳过 |

### 2.5 入场时机

- **下限**：T=0（窗口开启即允许入场）
- **截止**：T=9min（540s），超过后本窗口禁止开单，等待下一窗口

## 三、持仓期信号监控（核心理念）

### 3.1 核心问题

当前方案只利用了**入场时**的信号。持仓期间信号会持续变化：
- 原本做 UP，RSI 持续走强 → 趋势可能延续
- 原本做 UP，RSI 开始回落、MACD 死叉 → 趋势可能反转

**解决方案：每次 `check_exit` 被调用时，同步获取当前实时信号（Core 6 + Advanced 5），用于辅助退出决策。**

### 3.2 信号共识实时分数

持仓期间，用一个**实时共识分数**评估趋势是否仍在：

```
realtime_agree = 实时 Core 6 同向数量（0~6）
entry_agree    = 入场时 Core 6 同向数量（0~6）
```

## 四、信号辅助退出决策（三重门）

### 4.1 第一重门：信号反向早平（止损辅助）

**触发条件：**

```
持仓方向为 UP：
  当前 Core 共识 DOWN 数量 ≥ 4/6

持仓方向为 DOWN：
  当前 Core 共识 UP 数量 ≥ 4/6
```

**行为：**
- 立即触发**提前止损**（不等固定 SL 触发）
- `pnl_pct` 可能为正也可能为负
- 优先保护利润，防止趋势彻底反转

**为什么 ≥ 4/6 而不是 > 3/6：**
- 防止过度敏感，避免被偶发噪音触发
- 4/6 意味着绝大多数指标已转向，趋势反转概率高

```
入场时 Core=5/6 UP，入场后 Core=4/6 DOWN
→ 提前止损：信号已强烈反转，不必等待
```

### 4.2 第二重门：TP 信号续持（止盈辅助）

**场景一：TP 阈值触发，但信号强烈延续**

```
持仓方向为 UP：
  当前概率移动 ≥ dynamic_tp1（+15%~22%）
  当前 Core 共识 UP ≥ 4/6

持仓方向为 DOWN：
  当前概率移动 ≥ dynamic_tp1
  当前 Core 共识 DOWN ≥ 4/6
```

**行为：**
- **跳过本轮止盈，继续持仓**
- 让利润继续奔跑
- 等待信号反转或更高止盈阈值触发

**场景二：TP1 已触发止盈 50%，剩余 50% 持仓**

```
TP2 阈值触发（+30%~45%）
当前 Core 共识同向 ≥ 3/6（保留持仓）
```

**行为：**
- 再次跳过止盈，继续持仓
- 只在信号反转（≥ 4/6 反向）或窗口到期时平仓

### 4.3 第三重门：移动止损信号增强

**趋势加强时（信号持续同向）：**
```
当前 Core 共识同向 ≥ 4/6：
  移动止损间距扩大 ×1.5
  例如：原间距 20% → 扩大至 30%
  → 允许更大的回撤，给趋势更多的呼吸空间
```

**趋势减弱时（信号转弱）：**
```
当前 Core 共识同向 < 3/6：
  移动止损间距收紧 ×0.75
  例如：原间距 20% → 收紧至 15%
  → 信号模糊时快速锁定利润
```

**信号反转时（强反向）：**
```
当前 Core 共识反向 ≥ 4/6：
  立即激活移动止损（不等概率涨到 70%）
  移动止损线 = 当前价 - 10%（极保守保护）
```

### 4.4 三重门决策矩阵

| 市场状态 | 条件 | 行为 |
|---|---|---|
| 信号强烈延续 | realtime_agree ≥ 4/6 同向 | **续持**（跳过 TP，放宽移动止损） |
| 信号中度延续 | realtime_agree = 3/6 同向 | 标准行为（按 ATR 阈值止盈止损） |
| 信号模糊 | realtime_agree < 3/6 | 收紧移动止损，快速锁定利润 |
| 信号反转 | 反向 agree ≥ 4/6 | **早平**（不等 SL，直接离场） |
| 信号极端反转 | CVD 反向（Advanced） | **立即平仓**（最强单信号） |

## 五、概率 ATR 动态阈值

### 5.1 为什么用概率 ATR

Polymarket 二元合约价格本质是**概率值（0~1）**，传统价格 ATR 需要适配为概率 ATR：

```
概率 ATR = 最近 N 个 tick 内，UP/DOWN 价格对真实波动幅度的 EMA 均值
```

### 5.2 计算方法

```
TR_t = max(
    |UP_t - UP_{t-1}|,          # UP 方向的波动
    |UP_t - DOWN_{t-1}|,        # UP 对上一 DOWN 的跨越
    |UP_{t-1} - DOWN_{t-1}|     # 跨窗口真实波动
)

ATR = EMA(TR_1, ..., TR_N)      # N=6，alpha = 2/(N+1)
```

每次 `check_exit` 调用时记录价格快照（`_record_price_tick`），保留最近 20 个 tick 供计算。

### 5.3 动态阈值公式

**阈值公式：**

```
atr_mult    = min(1.0 + atr_value / 0.02, 3.0)
trend_mult  = 1.2 (>70) / 1.0 (50~70) / 0.85 (30~50) / 0.75 (<30)
dyn_sl      = clamp(base_sl × atr_mult, -30%, -5%)
dyn_tp1     = max(base_tp1 × atr_mult × trend_mult, +8%)
dyn_tp2     = max(base_tp2 × atr_mult × trend_mult, tp1+5%)
trailing_gap = 0.20 / trend_mult
```

| 波动状态 | ATR | atr_mult | 趋势 | trend_mult | 动态止损 | 动态 TP1 | 动态 TP2 | trailing_gap |
|---|---|---|---|---|---|---|---|---|
| 波动正常+强趋势 | 1% | 1.5× | 强 | 1.0 | -15% | +22.5% | +45.0% | 0.200 |
| 波动正常+极强趋势 | 1% | 1.5× | 极强 | 1.2 | -15% | +27.0% | +54.0% | 0.167 |
| 波动剧烈+弱趋势 | 3% | 2.5× | 弱 | 0.75 | -25% | +28.1% | +56.3% | 0.267 |
| 波动极小+强趋势 | 0.5% | 1.25× | 强 | 1.0 | -12.5% | +18.8% | +37.5% | 0.200 |

**上下限保护：**
- 止损：-30% ~ -5%
- TP1：+8% ~ 无上限
- TP2：始终高于 TP1 +5%

## 六、趋势强度叠加（阶段二）

### 6.1 趋势强度指标

在 `exit_controller.py` 中计算 `_compute_trend_strength()`，基于持仓期的实时指标：

```
trend_strength = RSI偏离中性×0.25 + MACD动能×0.20 + 布林带位置×0.15
              + VWAP偏离×0.15 + Core共识分数×0.25
```

| 组成 | 计算方式 |
|---|---|
| RSI 偏离（权重 25%） | `abs(rsi_val - 50.0) × 2`，范围 0~100 |
| MACD 动能（权重 20%） | 最近3个 histogram 均值，方向与持仓一致时为正 |
| 布林带位置（权重 15%） | 触及边缘（upper_touch/lower_touch）→80，否则 40 |
| VWAP 偏离（权重 15%） | 价格在 VWAP 上下方 →80，否则 30 |
| Core 共识分数（权重 25%） | RSI偏离×0.5 + MACD动能×0.5 |

### 6.2 趋势强度 × 动态阈值叠加

```
最终 TP1 = base_tp1 × atr_mult × trend_mult
最终 TP2 = base_tp2 × atr_mult × trend_mult
移动止损间距 = 0.20 / trend_mult   （趋势强则 gap 更大，弱则收紧）
```

| 趋势强度 | trend_mult | TP1/TP2 效果 | trailing_gap |
|---|---|---|---|
| 极强（>70） | ×1.2 | 目标 +20% | 0.167（更宽，允许更大回撤） |
| 强（50~70） | ×1.0 | 标准行为 | 0.200（不变） |
| 中（30~50） | ×0.85 | 目标 -15% | 0.235（收紧） |
| 弱（<30） | ×0.75 | 目标 -25% | 0.267（最紧，快速锁定利润） |

**注意：** 此处 ATR 与趋势强度各自独立叠加，先 ATR 后趋势（乘法叠加），最终效果为 `base × atr_mult × trend_mult`。

### 6.3 趋势强度对三重门的影响

- Gate1（信号反转早平）：与趋势强度无关，任何时候 reverse ≥ 4/6 都立即退出
- Gate2（信号续持）：与趋势强度无关，TP 触发时信号同向即跳过止盈
- Gate3（移动止损）：**受趋势强度直接影响**，极强趋势使用更宽 gap，弱趋势收紧

## 七、AI API 辅助决策（阶段三）

### 7.1 定位

AI 不控制方向（方向由信号系统决定），只负责**「在哪里退出」**。

### 7.2 输入数据

```json
{
  "asset": "BTC",
  "entry_price": 0.52,
  "entry_core_agree": 5,
  "realtime_core_agree": 4,
  "atr_probability": 0.03,
  "atr_multiplier": 1.5,
  "trend_strength": 65,
  "pnl_pct": 18.5,
  "window_remaining_sec": 420,
  "rsi": 38,
  "macd_histogram": 0.0008,
  "funding_rate": 0.0001,
  "cvd_zscore": 1.2,
  "position_side": "UP"
}
```

### 7.3 AI 输出

```json
{
  "recommended_sl_pct": -15.0,
  "recommended_tp1_delta": 20.0,
  "recommended_tp2_delta": 35.0,
  "trailing_gap_pct": 0.20,
  "signal_override": "continue_holding",
  "confidence": 0.78,
  "regime": "trending"
}
```

### 7.4 signal_override 含义

| signal_override | 含义 |
|---|---|
| `"continue_holding"` | 信号续持，延迟 TP |
| `"take_profit_now"` | 信号已弱，建议立即 TP |
| `"tighten_stop"` | 收紧移动止损 |
| `"emergency_exit"` | CVD 反向等极端情况，立即离场 |

## 十、注意事项

1. **回测优先于实盘**：信号辅助退出涉及较多参数（续持阈值 3/6 vs 4/6），需先在 dry 模式验证
2. **信号延迟**：Binance API 调用有 ~200-500ms 延迟，持仓极短（秒级）时需注意
3. **窗口末期**：窗口剩余 < 60 秒时，无论信号如何，优先持有到期结算
4. **日志完善**：`tp_hit` 数据中记录 `realtime_agree`、`signal_override`、`atr_value`，便于分析
5. **并发安全**：`IndicatorSignalService` 内部已有模块级历史（RSI/OI/CVD），多币种时需确认无竞态
